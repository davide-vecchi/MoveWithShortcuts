# Module MoveWithShortcuts

# Changelog

## [3.1.0-SNAPSHOT]


### Changed

- The confirmation prompt now mentions the shortcut-file renaming when the selected `-shortcut-file-name` policy
  applies, and warns when a policy other than `never` is given but the file or folder name is unchanged (a pure move),
  so no shortcut file can be renamed.

- `-shortcut-file-name` collisions now use the next free numbered variant of the new name (e.g. `Finance2.xlsx.lnk`),
  preserving the Windows default suffix and never replacing the existing file ; the collision is shown in the final
  summary.

- Update the DFile dependency to its latest version and use its new overload of listFiles() to always read the shortcuts
  sorted by timestamp ascending, so the ones that will get modified will be in the same relative order of their
  timestamp.

- Update the DApplication dependency to 2.4.0-SNAPSHOT .

- Update the DUtil dependency to 2.4.0-SNAPSHOT .

- Improve some user messages.


### Added

- When started with some named options, MWS now asks interactively only for the missing required options (`-from`,
  `-to`, `-search`); optional options use their defaults. Zero arguments keep the fully interactive flow, including
  the verbosity prompt.

- The optional `-shortcut-file-name <never|exact|descendant>` argument (default `never`) : `exact` / `descendant` also
  rename the shortcut files named after the renamed / moved leaf, preserving the Windows default `" - <suffix>"` part
  when present. The final summary now also shows the renamed, collision and rename-skipped counts.

- Named command-line arguments, replacing the positional ones : `-from <file or folder path> -to <value> -search
  <folder path> [-verbosity <int>] [-help]`, handled through the new `DCommandLineArg` DLib (all-lowercase option
  names, case-insensitive parsing, usage text generated by the library). Running with no arguments still starts the
  interactive mode.


### Removed

- The positional command-line form (`originalPath destinationPath searchPath [verbosity]`), replaced by the named
  one.


### Fixed

- The `-from` / `-to` help text now describes both accepted situations : either the move / rename must be
  performed, or it was already done elsewhere and only the shortcut adjustment is performed.

- The `MoveWithShortcuts.BAT` and `MoveWithShortcuts.ps1` launchers now forward their command-line arguments to the
  program instead of ignoring them.

- The updated `DFile` dependency also fixes MWS setting an empty work folder ("Start in") in the updated shortcuts
  instead of remapping it to the new target's parent folder, when moving / renaming a file or folder.


### Internal changes

- Make some private constructors protected.
  For the factory method pattern there is no need that all constructors are private, which would signal
  non-extensibility and make the class effectively final. If one doesn't want to signal non-extensibility, constructors
  can be protected instead.
